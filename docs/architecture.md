# ARCHITECTURE

The current mentor-only workflow, manual asynchronous roster sync and scoped kiosk sessions are described in [mentor roster architecture](mentor-roster.md). Internal Staff/API_SCOPE and stats:staff names are retained for deployed-resource and Stats compatibility; public Puncher terminology is mentor.

Puncher uses React/Vite, TypeScript, Node 24 Lambda, DynamoDB and TypeScript CDK. One language makes domain rules, UI DTOs and infrastructure approachable for students; React introduces a second frontend convention alongside the team's Angular app but avoids a large component framework. Plain accessible controls and CSS keep maintenance small. Business rules live in service/domain.ts, persistence in service/store.ts, and the same HTTP dispatcher serves Lambda and the local Node adapter.

Inspected FMEA main commit 8e9afec5d1db54557d886dd9c835b904166e92d5: README, workspace/service manifests, Google verification/authorizer, local adapter, create-FMEA handler, CDK backend/frontend/certificate/config/bin and deploy workflow. Reference: https://github.com/STMARobotics/fmea-app. Adopt lowercase table keys, optional GSI1/GSI2, GIS server verification, HTTP API Lambda authorizer without caching, same-origin API, private S3/OAC and separate regional stacks. Do not reuse any FMEA resource, OAuth ID, hosted zone ID or deployment role. Local DynamoDB endpoint support is an intentional extension.

All mutable entity records have a version. Transactions condition every read entity on its version (or absence), so independent Lambda instances cannot overwrite each other's decisions. Barcode claims and event participation claims are transactional. Shop operations retain durable idempotency tombstones without TTL: after the 24-hour response retention window replay fails closed, rather than becoming a new toggle. Device/operation IDs and payload hashes scope replay. Full card numbers never appear in public confirmations or logs.

The current-session record holds the last scan time, current session reference, and persistent warning. Active discovery uses a dedicated ACTIVE partition with exact session references. Cleanup paginates this partition and conditionally expires the exact current session; catch-up includes every cutoff before now. Reads enforce expiry even before cleanup. America/Chicago calendar arithmetic uses Temporal; no fixed offset or 24-hour-day arithmetic. Warning delivery uses a device-bound operation acknowledgment after rendering; until acknowledged every later confirmation carries the warning.

Stats is a separate read-only backend and deployment. Only Puncher writes the canonical table. See stats-integration.md. No browser storage is authoritative and no offline attendance queue exists.

Human sign-in uses Google's authorization-code flow with state, nonce and PKCE. The Lambda exchanges the code using a client secret held in Standard SSM Parameter Store SecureString, then creates a seven-day opaque HttpOnly cookie session in Puncher's existing DynamoDB table. Only a hash of the cookie value is stored; Lambda authorizers perform uncached session lookup and permissions are rechecked on every request. This session is app-specific and does not require the separate Angular app to share Puncher's database or cookies.

The owner later requested a simpler kiosk with three anonymous team shop totals. These are served through a separate device-authorized ShopTotals Lambda, with read-only access to roster discovery/canonical shop credits and narrowly scoped writes to SUMMARY#SHOP plus device rate records. A 60-second database cache and a conditional expiring refresh lease bound work across Lambda instances. This is a disposable display projection, never another attendance record or a replacement for Stats reporting. See api.md for eligibility, periods, reconciliation and failure behavior.

The UI now follows FMEA's current neutral #050607 page background, #08090b header, #151719/#101113 panels, #292d32 borders, #75baff navigation/focus accents, and #123225/#a6f1cd action buttons. Figtree remains the app font. Reference styles: https://github.com/STMARobotics/fmea-app/blob/main/ui/src/styles.scss and https://github.com/STMARobotics/fmea-app/blob/main/ui/src/app/teams-seasons-page/teams-seasons-page.component.scss. Kiosk copy is reduced to the scan prompt, save/error confirmations and required warnings.

The owner subsequently authorized a current-presence name splash on the kiosk. It uses a separate names-only device DTO derived from ACTIVE plus authoritative CURRENT/session/member checks; it does not reuse the administrator roster response. The frontend renders initials/name tiles and a count, polls every ten seconds and refreshes immediately after scans. Each sample expires in at most fifteen seconds or at the session cutoff, and failures clear the displayed names. Existing kiosk table-key permissions suffice. No email/card/member IDs or history are exposed.

The scan box has a decorative rounded-perimeter chase and inner glow. Its idle loop is 16 seconds; a scan accelerates the existing animation over 180 ms, then coasts back to idle over 5.2 seconds without resetting its border position. A 2.2-second inset flash fades independently. Color follows the actual UI state (blue while saving, green only after a saved result, red on failure). Web Animations handles the idle loop; requestAnimationFrame is used only during the brief speed change. At the owner's explicit request, the kiosk animation is always on, including when the browser reports reduced motion. There is no motion dropdown or stored preference; the obsolete puncher-motion value is ignored. Animation cleanup does not affect scanning, requests, or confirmation timers. Date and time are centered above the scan box, and the redundant SHOP/Completed visits labels are removed.
